## Boolean scalar relationship questions

Trace each Boolean atom in the overflow guards through its actual
ConditionEvaluationId, invocation context, kind, cause, recorded constant and
true/false inspection evidence. `validate_guard` currently rejects an atom
opposite a recorded constant; the producer's `channel_record_boolean_identity`
already filters the opposite branch when `Value.constant` is known. These
source paths do not establish whether the relevant actual values stay known.

For named calls, compare the real evaluated argument, frozen whole-argument
CopyInvocation snapshot, read-received binding, selected condition evaluation
and any returned/recaptured Boolean. Parameter index, physical application ID
and context are required; equal spans or spellings cannot relate two executions.
If a stage lacks an immutable historical snapshot, report that missing evidence
instead of consulting the final mutable binding as its source proof.

Local code inspection shows ordinary read-parameter reception copies Value and
changes permission/construction flags; it does not by itself prove constants
are lost. ConditionEvaluation records the constant available at evaluation.
Measure literal true/false inputs, forwarded scalars, callbacks, defaults and
wrapper projections before attributing the explosion to a particular stage.
An unknown caller stays unknown. A literal actual call cannot stand in for
the independently checked universal function declaration.

Any future BoolSource contract needs independent Source reconstruction and
tests for changed actual arguments, swapped evaluation identities, mismatched
callee/caller, mutable writes after capture, unknown callbacks and incremental
edits. Immutable detached scalar copies retain their old bit; a write to a
mutable cell cannot reuse its previous predicate. No same-span truth cache or
type-level equality supplies this evidence. Root must review such a contract.

## Assert, abnormal exits and scope continuation

In the inspected source path, builtin assert returns Unit, and the expression
hook selects/inspects its true condition. Explicit panic returns abnormal Never.
This alone does not show how every assert-failure continuation is represented;
other flow/cleanup machinery and the actual record stream must be inspected.
Record the chosen condition, each false alternative, Abnormal and Complete
receipts, activation, returned outcome and the first subsequent operation.

The independent replay currently treats Complete as a coverage receipt with
no state change. Abnormal validates its abnormal carrier and returns without
deleting the Case. Observe whether the failed-assert path terminates its frame,
unwinds cleanup, becomes a caught scope/task Result, or continues outside the
handler. A caught scope fault can return normally to its caller; it is not a
reason to delete the whole outer execution or waive caller-owned debt.

Distinguish language panic/cancellation/effect abort from an ordinary business
Err and from unexpected Rust failure. An absence of later active operations
does not itself certify termination. Root owns any public lifecycle/control-flow
contract required to reconstruct the path.

## Task, clock and executed-history questions

TaskJoin currently merges the child's actual clock into its parent but does
not simply remove its task/clock entries. Scope/receiver exits remove queues
under their rules and retain closed-anchor evidence; Complete does not clear
history. Record preceding fork/join, source scope completion and exact guard
coverage for each divergent actor or executed ID.

A prior join or closed scope is only an observed history candidate. Future
guard terms, Result aliases, returned closures, queued packet clocks, cleanup,
handlers, resumes, external callbacks and scoped/root references may still
depend on it. Probe future references in the actual remaining record stream
and frozen value graph, including aliases and producer generations. That scan
is diagnostic; an unresolved or opaque source dependency cannot prove death.

Do not remove old clock coordinates because their actors look completed, or
old executed IDs because their channel looks closed. Both are used to interpret
future operations and their guard availability. A future state-liveness or
symbolic-history representation must retain correlations and be reviewed by
Root, with an independent concrete model and adversarial alias/cleanup tests.
