# Repository guidance

## Editing restrictions

Do not modify `README.md` or `AGENTS.md` unless the user explicitly requests it.

## Git workflow

Work directly on `main` and commit changes there. Do not create, switch to, or
use other branches unless the user explicitly requests them.

## Ril distinctions

[SPEC](doc/SPEC.md) is canonical. Keep this guide focused on distinctions that are easily confused and affect interpretation or implementation. The table summarizes language rules and introduces no additional conformance requirements.

| Distinction | Ril meaning |
| --- | --- |
| [Checking / execution](doc/SPEC.md#complete-provenance-and-required-annotations) | Modes, provenance, and effects are static judgments retained in interfaces and erased before code generation. Mutation, copying, handlers, and cleanup execute. |
| [Values / shared objects](doc/SPEC.md#types-and-memory-model) | `bool`, `int`, `f64`, `str`, `bytes`, and `()` copy by value and forbid `ref`/`mut`/`^mut`. Records, nonempty tuples, collections, and sums have GC-managed identity; aliasing grants no write authority. |
| [`int` / `f64`](doc/SPEC.md#numeric-literals) | `int` is arbitrary-precision signed; `f64` is binary64. Literals have no width suffixes, and numeric conversion is explicit. |
| [Records / constructors](doc/SPEC.md#sum-types-and-variant-spreading) | Record forms attach `.{...}` (`User.{ id: 1 }`). Variant and non-record nominal payloads use whitespace (`Ok 42`, `Ok ()`, `Some .{ x: 1 }`); unit constructors stand alone. Sum and effect declarations use outer `{...}`. |
| [Aliases / nominal / opaque types](doc/SPEC.md#nominal-type-alias-and-opaque-types) | `type A = B` is transparent; `type A B` is a distinct wrapper, unwrapped by `inner`. `.ril` `opaque type` seals representation outside its exact defining file or `sub`, including parent/child scopes. |
| [Binding / access](doc/SPEC.md#binding-modes-and-storage-matrix) | `let`/`var` govern slot replacement; plain bindings hold deeply immutable snapshots. `ref` may observe a live writable origin. Pinning fixes the target object, independent of GC movement. |
| [`mut` / `^mut`](doc/SPEC.md#parameter-modes-caller-obligations-and-defaults) | `mut` grants write access; `^mut` acknowledges retained shared writers. Concrete modes match exactly, including nested members/elements: `^mut` requires a `^mut` receiver. Source-overlap checks do not relax mode matching. |
| [Authority / reachable use](doc/SPEC.md#reachable-authority-use) | `var` requires slot replacement; `mut` requires writable or consuming use. Shared locals require shared reception and writable use; `^mut` parameters require surviving retention. Contextual callback/handler `_`/`_name` binders are exempt; declared member schemas have no independent use requirement. |
| [`new` / reception](doc/SPEC.md#return-construction-access-modes-and-sources) | The receiver selects legal modes for new regions. Contained old sources retain their permissions and aliases; `&return{...}` records them. Without old sources, `new` promises a complete new graph. `new x` preserves identity and ends `x` and dependent paths; independent old-source paths remain valid. |
| [`via` / `infer`](doc/SPEC.md#access-mode-inference-with-via-and-infer) | `via` binds static mode templates; lexical `let via` preserves dependent modes and origins. `-> infer T` derives result modes/provenance, keeps `T` explicit, and requires explicit `via` in that callable's own parameter list. |
| [Mode inference / fixed storage](doc/SPEC.md#member-modes-and-implicit-schema-parameters) | Ordinary access and replacement use the received schema. Qualified `new` reception may select modes for new regions; old-source permissions stay fixed. Concrete non-`via` calls require explicit argument markers, also written after `\|>` in pipelines. |
| [Root / contained origins](doc/SPEC.md#return-construction-access-modes-and-sources) | `ref(x)`/`^mut(x)` select roots from the formal's call-entry graph. `&return{x, ref y, ^mut z}` records contained immutable, read-only, and shared writable sources. Projection and unwrapping preserve the selected source's own qualification. Root writable return accounts for its own retention; additional writes/sharing need separate clauses. |
| [State / environment creation](doc/SPEC.md#local-state-discharge-parameter-mutation-and-sharing) | `&mut` records parameter writes, `&^mut` independent retained sharing, and `&capture` surviving environment creation. Pure immutable captures still require factory `&capture` but may match pure callable targets; confined local writes discharge. |
| [`&up` / module constants](doc/SPEC.md#state-groups-and-captured-layers) | Callable-type `&up` abstracts a closure environment; named local functions list captured bindings in `&up{...}`. Module/`sub` constants are pure and need no `&up`; mutable/live top-level state is prohibited. |
| [Definition / callable target](doc/SPEC.md#callable-contract-matching) | Named definitions spell exact exercised effects and state/provenance clauses; anonymous closures infer them. Callable effect/state rows are upper bounds; access modes and return-source guarantees also match. Pure state reduction preserves return-source relations. Omitted rows are closed empty; `@`, `&`, and `@&` open rows only on callable types. |
| [Fixtures / complete source](doc/SPEC.md#document-conventions) | SPEC fixtures may show compiler-completed named signatures; complete source spells required annotations. |
| [Purity / normal continuation](doc/SPEC.md#failure-model-and-purity) | Purity means empty outward operational effects and state reduced to `&{}` after discharge; it promises no termination. `never` means no normal continuation, including panic or `while true` without a targeting `break`. |
| [Recoverable errors / panic](doc/SPEC.md#mandatory-inspection-of-fallible-results) | `Result` must be inspected, propagated, handled, or returned; `_` does not inspect it. Defects unwind LIFO cleanup; `absorb_panic` contains only unwind-safe computations without external live state or unhandled effects. |
| [Effect handlers / resource cleanup](doc/SPEC.md#scoped-resource-bindings) | `with Eff::op(...) -> ...` installs handlers for the remaining block; `with let` confines a resource whose type declares `with close`. Cleanup is LIFO on exit, panic, and cancellation; synchronous effects are allowed, `@Async` is prohibited. Effect handlers covering cleanup must precede the resource binding. |
| [User / system effects](doc/SPEC.md#effect-declarations-and-handlers) | `eff` operations are direct one-shot `fn` capabilities dispatched lexically; handler-arm operations reach outer handlers. `@Io` and `@Async` are system effects, not user-handler targets. |
| [Async suspension / isolation](doc/SPEC.md#structured-async-concurrency-and-channels) | `Async::run` discharges `@Async`, not `@Io`. `Scope`/`Task` are nursery-bound; fiber closures reject live/writable/`var` captures and stateful outer handlers. Single-shot calls may receive qualified `new` captures once; contained sources also satisfy isolation. Task/channel payloads preserve their own qualification. `Sendable` does not permit shared mutation. |
| [Foreign handles / ordinary objects](doc/SPEC.md#external-interface-declarations) | `.d.ril` opaque handles are exclusive affine host resources, not ordinary `.ril` opaque snapshots. They admit `new`/`mut`/`ref` and `with let`, but forbid cloning, freezing, equality, shared writers, and array storage. |
| [`clone` / `derive`](doc/SPEC.md#functional-updates-via-derive) | `clone` deep-copies ordinary shared objects into isolated `new T`, preserving internal aliases/cycles. `derive` updates immutable snapshots through confined `Draft<T>` paths with structural sharing and forwards recipe obligations. Neither accepts value-type roots. |
| [Built-ins / foreign declarations](doc/SPEC.md#named-function-declarations-and-contrast-matrix) | Bodyless `.ril` functions must match a registered primitive's module/name identity and signature. Primitive contracts determine phase (`len`, `assert`, `panic`, and `String::inspect` are dual-phase); names alone grant no primitive behavior. Foreign host declarations belong in bodyless `.d.ril`. |
| [`fn` / `meta fn` / type functions](doc/SPEC.md#disjoint-call-families-and-branch-pruning) | Ordinary `fn` runs at runtime; `meta fn` produces token-free static data; type functions produce type tokens. Direct saturated `meta fn` calls with static arguments fold to immutable runtime snapshots without `new` freshness; `meta fn` has no first-class runtime value. Static roots have an uncatchable compiler step limit (`E0811`). |
| [Static types / ordinary data](doc/SPEC.md#static-type-values-and-type-quotation) | `Type<T>` is an exact static metatype; bare `Type` is a sort. `<T>` quotes a token, `<tok>` in a type unquotes it, and `typeof e` checks without evaluating `e`. Runtime storage cannot hold tokens; generic `match <T>` specializes static metadata. |
| [Type / value arguments](doc/SPEC.md#generic-parameters-defaults-and-value-sorts) | Declared sorts control generic arguments. Values/tokens cannot supply type parameters; use `typeof e`. Type syntax adapts one-way to a `Type<T>` value parameter. `T: int \| f64` restricts a static domain; each call selects one rigid type, not a runtime union. |
| [Sum inclusion / subtyping](doc/SPEC.md#sum-variant-spreading-and-subset-conversion) | `..Sub` spreads variants; `?` widens included error sums, while ordinary values use `as Sup`. This is distinct from general subtyping. Extensible sums require a wildcard outside their defining package; closed records have no width subtyping. |
| [Data shape / member metadata](doc/SPEC.md#static-introspection) | `T.(k)` projects constituent data types; `coords(<T>)` retains `(MemberMode, key)` pairs, while `variants(<T>)` lists sum tags. Value-level payload projection requires matching or narrowing. |
| [`where` / guards](doc/SPEC.md#dual-tier-where-invariants) | Braceless `where` hoists declarations: signature helpers admit `type`/`fn`/`meta fn`; trailing block helpers also admit `eff`. Type guards preserve the guarded type; static value guards return `<()>` to accept or `<never>` to reject. Signature value contracts invoke pure fallible guards at entry/successful exit. |
| [`is` / equality / patterns](doc/SPEC.md#value-tests-with-is) | `is` tests tags, shapes, ranges, and subsets without binding; leaves read existing values or expressions. Data `==` requires the same type; static type tokens compare represented types by definitional equality. Binding patterns introduce names. Failed payload comparison alone does not exclude a variant. |
| [Stable narrowing / live writes](doc/SPEC.md#flow-sensitive-type-narrowing) | Immutable paths narrow without a depth limit. Overlapping writes invalidate facts; an open-state call may invalidate live refinements when independence is unproved. A `ref` alone proves no independence. |
| [Package / module / executable root](doc/SPEC.md#modules-and-compilation-units) | `pkg/...`, `ril/...`, and dependency roots resolve imports; `pub(pkg)` is package visibility. Files are modules; inline `sub`s are hermetic and use `Super::` for parents. Executable roots are unimportable, forbid root visibility modifiers, and require private ordinary `fn main`. |
