# Repository guidance

## Editing restrictions

Do not modify `README.md` or `AGENTS.md` unless the user explicitly requests it.

## Git workflow

Work directly on `main` and commit changes there. Do not create, switch to, or
use other branches unless the user explicitly requests them.

## Ril distinctions

[SPEC](doc/SPEC.md) is canonical. Keep this guide focused on distinctions that are easily confused and affect interpretation or implementation. The table summarizes language rules and introduces no additional conformance requirements.

| Distinction | Ril meaning |
| --- | --- |
| [Checking / execution](doc/SPEC.md#complete-provenance-and-required-annotations) | Modes, provenance, and effects are purely static judgments retained in module semantic interfaces with no observable runtime representation. Mutation, copying, handlers, and cleanup execute. |
| [Values / shared objects](doc/SPEC.md#types-and-memory-model) | `bool`, `int`, `f64`, `str`, `bytes`, and `()` copy by value and forbid `ref`/`mut`/`^mut`. Records, nonempty tuples, collections, and sums have automatically reclaimed, location-independent object identity; aliasing grants no write authority. |
| [`int` / `f64`](doc/SPEC.md#numeric-literals) | `int` is arbitrary-precision signed; `f64` is binary64. Literals have no width suffixes, and numeric conversion is explicit. |
| [Records / constructors](doc/SPEC.md#sum-types-and-variant-spreading) | Record forms attach `.{...}` (`User.{ id: 1 }`). Payload variants and non-record nominal constructors use tight `(...)` (`Ok(42)`, `Ok()`, `Rect(10.0, 20.0)`, `UserId(42)`); unit constructors stand alone. Bare `{...}` blocks (`Block`, `sub`, `where`, `with`, `eff`, `match`, sum declarations) separate items with `;` or newline. |
| [Aliases / nominal / opaque types](doc/SPEC.md#nominal-type-alias-and-opaque-types) | `type A = B` is a transparent alias (equivalent to `B`); `type A B` (and unit `type A`) is a distinct nominal wrapper, unwrapped by `inner`. `.ril` `opaque type A B` (`opaque` is contextual before `type`) seals representation outside its exact defining file or `sub`, including parent/child scopes. |
| [Binding / access](doc/SPEC.md#binding-modes-and-storage-matrix) | `let`/`var` govern slot replacement; plain bindings hold deeply immutable snapshots. `ref` may observe a live writable source or anchor a `new` live-`ref` composite/`&up(ref)` closure. Pinning fixes the target object, independent of physical object relocation. |
| [`mut` / `^mut`](doc/SPEC.md#parameter-modes-caller-obligations-and-defaults) | `mut` grants write access; `^mut` acknowledges retained shared writers (including stored local closures capturing outer `let mut`). Concrete modes match exactly, including nested members/elements: `^mut` requires a `^mut` receiver. Source-overlap checks do not relax mode matching. |
| [Authority / reachable use](doc/SPEC.md#reachable-authority-use) | `var` requires slot replacement; `mut` requires writable or `new`-handoff use. Shared locals require shared reception and writable use; `^mut` parameters require surviving retention. Contextual callback/handler `_`/`_name` binders are exempt; declared member schemas have no independent use requirement. |
| [`new` / reception](doc/SPEC.md#return-construction-access-modes-and-sources) | The target selects legal access modes for `new` subgraphs; named `fn`s returning `new` shared objects must faithfully declare `-> new T` rather than freezing unilaterally. Contained existing sources retain their authority and aliases; `&return(...)` records them. Without existing sources, `new` promises a complete `new` graph. Explicit `new x` (including at returns) preserves identity and ends `x` and dependent paths; independent existing-source paths remain valid. |
| [`via` / `infer`](doc/SPEC.md#access-mode-inference-with-via-and-infer) | `via` binds static mode templates; lexical `let via` (and `if let`/`while let`/`let ... else`/`for`/`match` `via`) preserves dependent modes and sources. `-> infer T` derives result modes/provenance, keeps `T` explicit, and requires explicit `via` in that callable's own parameter list. |
| [Mode inference / fixed storage](doc/SPEC.md#member-modes-and-implicit-schema-parameters) | Ordinary access and replacement use the received schema. `new`-qualified reception may select access modes for `new` subgraphs without synthesizing `var` slot replaceability; existing-source authority stays fixed. Concrete non-`via` calls require explicit argument markers, also written after `\|>` in pipelines. |
| [Root / contained sources](doc/SPEC.md#return-construction-access-modes-and-sources) | `ref(x)`/`^mut(x)` select roots from the formal's call-entry graph. `&return(x, ref y, ^mut z)` records contained immutable, read-only, and shared writable sources. Projection and unwrapping preserve the selected source's own qualification. Root writable return accounts for its own retention; additional writes/sharing need separate clauses. |
| [State / environment creation](doc/SPEC.md#local-state-containment-parameter-mutation-and-sharing) | `&mut` records parameter writes, `&^mut` independent retained sharing, and `&capture` surviving environment creation. Pure immutable captures still require factory `&capture` but may match pure callable targets; confined local writes stay local. |
| [`&up` / module constants](doc/SPEC.md#state-groups-and-captured-layers) | Callable-type `&up` abstracts a closure environment; named local functions list captured bindings in `&up(...)`. Module/`sub` `let` (`ValueName`) and `meta let` (`ScreamingSnakeCase`, exclusive to `meta let`) constants are pure and need no `&up`; mutable/live top-level state is prohibited. |
| [Definition / callable target](doc/SPEC.md#callable-compatibility) | Named definitions spell exact exercised effects, state/provenance clauses, and return modes (`-> new`); anonymous closures infer them. Callable effect/state sets are upper bounds; access modes and return-source guarantees also match. Pure state reduction preserves return-source relations. Omitted sets are closed empty; `@`, `&`, and `@&` open compiler-tracked bounds on callable types (parameters, fields, collections) orthogonal to access modes. |
| [Snippets / complete source](doc/SPEC.md#document-conventions) | SPEC snippets may show compiler-completed named signatures; complete source files spell required annotations. |
| [Purity / normal completion](doc/SPEC.md#failure-model-and-purity) | Purity means empty outward effects and empty state after local containment; it promises no termination. `never` means no normal completion, including panic or `while true` without a targeting `break`. |
| [Recoverable errors / panic](doc/SPEC.md#mandatory-inspection-of-fallible-results) | `!<T, E>` (`Result<T, E>`) must be inspected, propagated, handled, or returned; `_` does not inspect it. Defects unwind LIFO cleanup; `absorb_panic` contains only panic-isolated computations without outer live state or unhandled effects. |
| [Effect handlers / resource cleanup](doc/SPEC.md#scoped-resource-bindings) | `with Eff::op = [mode] expr` installs handlers for the remaining block; `use [mut] x = ...` confines a resource whose type declares `use(close)`. Cleanup is LIFO on exit, panic, and cancellation; synchronous effects are allowed, `@fiber` is prohibited. Effect handlers covering cleanup must precede the resource binding. |
| [User / system effects](doc/SPEC.md#effect-declarations-and-handlers) | `eff` operations are direct call-and-return `fn` operations dispatched lexically (no continuation capture); handler-arm operations reach outer handlers. `@io` and `@fiber` are lowercase system effects, not user-handler targets. |
| [Fiber suspension / isolation](doc/SPEC.md#structured-fiber-concurrency-and-channels) | `Fiber::run` runs and handles `@fiber`, not `@io`. `Scope`/`Task` are task-scope-bound; fiber closures reject live/writable/`var` captures and stateful outer handlers. Run-once calls may hand off `new`-qualified captures once; contained sources also satisfy isolation. Task/channel payloads preserve their own qualification. `Sendable` does not permit shared mutation. |
| [Foreign handles / ordinary objects](doc/SPEC.md#foreign-interface-declarations) | `.d.ril` opaque handles are exclusive, non-duplicable host resources, not ordinary `.ril` opaque snapshots. They admit `new`/`mut`/`ref` and `use`, but forbid cloning, freezing, equality, shared writers, and array storage. |
| [`clone` / `derive`](doc/SPEC.md#functional-updates-via-derive) | `clone` deep-copies ordinary shared objects into isolated `new T`, preserving internal aliases/cycles. `derive` updates immutable snapshots through confined `Draft<T>` paths (leaving the base unchanged; implementations may structurally share unchanged subgraphs) and forwards the `derive` closure's obligations. Neither accepts value-type roots. |
| [Built-ins / foreign declarations](doc/SPEC.md#named-function-declarations-and-contrast-matrix) | Bodyless `.ril` functions must match a registered primitive's module/name identity and signature. Built-in specifications determine phase (`len`, `assert`, `panic`, and `String::inspect` are dual-phase); names alone grant no primitive behavior. Foreign host declarations belong in bodyless `.d.ril`. |
| [`fn` / `meta fn` / type functions](doc/SPEC.md#disjoint-call-families-and-branch-pruning) | Ordinary `fn` runs at runtime; `meta fn` produces type-value-free static data; type functions produce static type values. Direct saturated `meta fn` calls with static arguments evaluate at compile time to immutable runtime snapshots without `new` qualification; `meta fn` has no first-class runtime value. Static roots have an uncatchable compiler step limit (`E0811`). |
| [Static type values / ordinary data](doc/SPEC.md#static-type-values-and-type-quotation) | `Type<T>` is the exact static type of a type value representing `T`; bare `Type` is a kind. `<T>` quotes a type value, `<tv>` in a type unquotes it, and `typeof e` checks without evaluating `e`. Runtime storage cannot hold type values; generic `match <T>` resolves per concrete instantiation of `T`. |
| [Type / value arguments](doc/SPEC.md#generic-parameters-defaults-and-static-kinds) | Declared parameter kinds control generic arguments. Values and type values cannot supply type parameters; use `typeof e`. Type syntax adapts one-way to a `Type<T>` value parameter. `T: int \| f64` restricts a static domain; each call selects one concrete type, not a runtime union. |
| [Sum inclusion / subtyping](doc/SPEC.md#sum-variant-spreading-and-subset-conversion) | `..Sub` spreads variants; `?` widens included error sums, while ordinary values use `as Sup`. This is distinct from general subtyping. Extensible sums require a wildcard outside their defining package; closed records have no width subtyping. |
| [Data shape / field metadata](doc/SPEC.md#static-introspection) | `T.(k)` projects constituent data types; `fields(<T>)` retains `(FieldMode, key)` pairs, while `variants(<T>)` lists sum tags. Value-level payload projection requires matching or narrowing. |
| [`where` / checks & guards](doc/SPEC.md#dual-tier-where-invariants) | Braceless `where` hoists declarations: signature helpers admit `type`/`fn`/`meta fn`; trailing block helpers also admit `eff`. Static type checks preserve the checked type; static value checks return `<()>` to accept or `<never>` to reject. Signature guards invoke pure fallible guards at entry/successful exit. |
| [Equality / patterns](doc/SPEC.md#pattern-matching) | Data `==` requires the same type; static type values compare represented types by type equivalence. Binding patterns introduce names and unpack records, tuples, slices, ranges, and sum variants. |
| [Stable narrowing / live writes](doc/SPEC.md#flow-sensitive-type-narrowing) | Immutable paths narrow without a depth limit. Overlapping writes invalidate facts; an open-state call may invalidate live narrowings when independence is unproved. A `ref` alone proves no independence. |
| [Package / module / executable root](doc/SPEC.md#modules-and-compilation-units) | `pkg/...`, `ril/...`, and dependency roots resolve imports; `pkg` is package visibility. Files are modules; inline `sub`s are isolated and use `Super::` for parents. Executable roots are unimportable, forbid root visibility modifiers, and require private ordinary `fn main`. |
