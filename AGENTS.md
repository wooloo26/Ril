# Repository guidance

## Editing restrictions

Do not modify `README.md` or `AGENTS.md` unless the user explicitly requests it.

## Git workflow

Work directly on `main` and commit changes there. Do not create, switch to, or
use other branches unless the user explicitly requests them.

## Pre-1.0 / no legacy compatibility

Ril is an unstable pre-1.0 language. Do **not** add backward-compatibility shims,
legacy deserialization fallbacks, migration error messages ("has been removed",
"formerly", "legacy"), or version-bump ceremonies. Keep internal format, schema,
and cache versions at `1` (or omit versioning where unnecessary). Code, diagnostics,
tests, and documentation should state directly what Ril **is** today.

## Repository layout

- `doc/SPEC.md` — canonical language specification and diagnostic error code table.
- `std/` — embedded standard library (`prelude`, `array`, `map`, `set`, `string`, `bytes`, `numeric`, `reflect`, `panic`, `io`, `file`, `math`).
- `crates/` — compiler workspace in pipeline order:
  - `ril-source` (spans, interner, diagnostic codes) → `ril-syntax` (lexer, lossless CST/AST, formatter) → `ril-hir` (name resolution, visibility, stdlib/primitive manifest) → `ril-sema` (type checker, static eval, access/provenance Horn solver, panic/abort/termination analysis, `.rili` interfaces) → `ril-mir` (MIR lowering, LIFO `with`/`defer` scopes, stack promotion) → `ril-codegen` (Cranelift JIT/AOT) + `ril-rt` (GC, BigInt, `corosensei` `ctl` runtime, unwind; staticlib wrapper in `runtime/ril-rt-static`).
  - `ril-driver` (package loader, incremental cache, shared `inspect` projection), `ril-lsp` (LSP server & TypeScript VS Code extension), `ril-cli` (`ril` binary: `check`/`build`/`run`/`fmt`/`inspect`/`lsp`/`test`), `ril-test` (suite runner, protocol & Lean oracle harness).
- `tests/` (`.ril` conformance/runtime suites), `examples/` (sample packages), `formal/` (Lean 4 proofs & `horn-oracle`), `scripts/` (`doc_check`, `formal_check`), `fuzz/` (fuzz targets), `prek.toml` (Rust `prek` Git hooks for `pre-commit` + `commit-msg`, reusing `.githooks/commit-msg`).

## Ril is not Rust

Do not project Rust's ownership, borrowing, lifetime, or move vocabulary onto Ril:

| Rust concept (avoid conflating) | Ril reality |
| --- | --- |
| Ownership & lifetimes (`'a`) | Ril has **no memory ownership or lifetimes**. Shared objects are GC-reclaimed (including cycles) with location-independent identity; modes govern **static access authority**, not allocation or deallocation. |
| Borrowing & `&T` / `&mut T` | `ref`, `mut`, and `^mut` are **access modes**, not pointer/reference types (no `*x`, no borrow checker). In signatures, `&^mut`/`&up`/`&capture`/`&return(...)` are **state clauses**, never reference types. |
| Move semantics | Plain bindings (`let y = x`) share deeply immutable snapshots without invalidating `x`. `new` marks an **unbound newly created `SharedObject`** (plus exiting-scope promotion of pinned `let mut` locals / `new` parameters at block or function exit), never mid-scope Rust move semantics. |

## Ril distinctions

[SPEC](doc/SPEC.md) is canonical. Keep this guide focused on distinctions that are easily confused and affect interpretation or implementation. The table summarizes language rules and introduces no additional conformance requirements.

| Distinction | Ril meaning |
| --- | --- |
| [Checking / execution](doc/SPEC.md#complete-provenance-and-required-annotations) | Modes, provenance, and effects are purely static judgments retained in module semantic interfaces with no observable runtime representation. Mutation, copying, handlers, and cleanup execute. |
| [Values / shared objects](doc/SPEC.md#types-and-memory-model) | `bool`, `int`, `f64`, `str`, `bytes`, and `()` copy by value and forbid `ref`/`mut`/`^mut`. Records, nonempty tuples, collections, and sums have automatically reclaimed, location-independent object identity; aliasing grants no write authority. |
| [`int` / `f64`](doc/SPEC.md#numeric-literals) | `int` is arbitrary-precision signed; `f64` is binary64. Literals have no width suffixes, and numeric conversion is explicit. |
| [Records / constructors](doc/SPEC.md#sum-types-and-variant-spreading) | Anonymous records and record aliases attach `.{...}` (`Alias.{ id: 1 }`). Sum variants are default-qualified (`Shape::Rect(10.0, 20.0)`; prelude `Ok(42)`, `Ok()`, `Some(x)`) with tight `(...)`; payload nominal/opaque types wrap via tight `::(...)` (`UserId::(42)`, `User::(.{ id: 1 })`); unit constructors stand alone. Bare `{...}` blocks (`Block`, `sub`, `where`, `with`, `eff`, `match`, sum declarations) separate items with `;` or newline. |
| [Comments](doc/SPEC.md#comments) | Pure single-line `--` comments only (no `{- ... -}` block comments), avoiding `{` + unary `-` ambiguity (`fn neg() -> int {-1}`). Consecutive `--` lines before a declaration form doc comments supporting ```` ```ril ```` examples. |
| [Aliases / nominal / opaque / linear types](doc/SPEC.md#nominal-type-alias-and-opaque-types) | `type A = B` is a transparent type alias (equivalent to `B`); `type A(B)` (and unit `type A`) is an erased nominal type, unwrapped by `inner`. `opaque type A(B)` seals representation outside its exact defining file or `sub`, including parent/child scopes. Non-linear payload nominal/opaque types admit trailing immutable static proof invariants (`type Port(int) \|> Between<1, 65535>`): deeply immutable payloads only (`E0356`; forbidden on aliases/sums/units/`linear`, `E0120`), verified at `Name::(...)` construction (`E0323`), auto-seeded into the prover on use, forbidding `derive` (`E0536`) and `inner(mut/^mut)` (`E0406`); public non-opaque invariants are bidirectional across `.rili` (`E0552`) while `opaque` invariants stay sealed. Contextual `linear` (`[Visibility] ["opaque"] ["linear"] "type"`; forbids `=` aliases) marks user-defined must-consume linear types; opaque types wrapping must-consume payloads must declare `opaque linear type` (`E0625`). |
| [Binding / access](doc/SPEC.md#binding-modes-and-storage-matrix) | `let`/`var` govern slot replacement; unmarked bindings hold deeply immutable snapshots. `ref` observes a live or immutable object or anchors a `new` live-`ref` composite/`&up(ref)` closure. Pinning fixes the binding slot, independent of physical object relocation. |
| [`mut` / `^mut`](doc/SPEC.md#parameter-modes-caller-obligations-and-defaults) | `mut` grants write access; `^mut` acknowledges retained shared writers (including stored local closures capturing outer `let mut`). Concrete modes match exactly, including nested members/elements: `^mut` requires a `^mut` receiver. Source-overlap checks do not relax mode matching, and `^mut` cannot downgrade to `mut`/`ref` across unhandled `ctl`, open `@`, or unhandled `@Eff`. |
| [Authority / reachable use](doc/SPEC.md#reachable-authority-use) | `var` requires slot replacement; `mut` requires writable use. Shared locals require shared reception and writable use; `^mut` parameters require surviving retention. Named functions enforce minimal effects (`E0626`) and state clauses (`E0529`). Contextual callback/handler `_`/`_name` binders are exempt; declared member schemas have no independent use requirement. |
| [`new` / reception](doc/SPEC.md#return-construction-access-modes-and-sources) | `new` designates unbound newly constructed `SharedObject` subgraphs (no expression-level `new x` handoff); targets select access modes for `new` subgraphs, and named `fn`s returning `new` shared objects declare `-> new T`. Pinned `let mut` locals and `new` parameters promote to `new` at scope/function exit (directly or inside passive exit constructors without sibling overlap). Contained existing sources retain their authority and aliases; `&return(...)` records them. |
| [`via` / `infer`](doc/SPEC.md#access-mode-inference-with-via-and-infer) | `via` binds static mode templates; lexical `let via` (and `if let`/`while let`/`let ... else`/`for`/`match` `via`) preserves dependent modes and sources. `-> infer T` derives result modes/provenance, keeps `T` explicit, and requires explicit `via` in that callable's own parameter list. |
| [Mode inference / fixed storage](doc/SPEC.md#member-modes-and-implicit-schema-parameters) | Ordinary access and replacement use the received schema. `new`-qualified reception selects access modes for `new` subgraphs without synthesizing `var` slot replaceability; existing-source authority stays fixed. Concrete non-`via` calls require explicit argument markers, also written after `\|>` in pipelines. |
| [Root / contained sources](doc/SPEC.md#return-construction-access-modes-and-sources) | `ref(x)`/`^mut(x)` select roots from the formal's call-entry graph. `&return(x, ref y, ^mut z)` records contained immutable, read-only, and shared writable sources. Projection and unwrapping preserve the selected source's own qualification. Root writable return accounts for its own retention; additional writes/sharing need separate clauses. |
| [State / environment creation](doc/SPEC.md#local-state-containment-parameter-mutation-and-sharing) | Parameter mutation is declared directly by `mut`/`^mut` parameter modes (`E0527` requires writable use on `mut`). `&^mut` records independent retained sharing and `&capture` surviving environment creation. Pure immutable captures still require factory `&capture` but match pure callable targets; confined local writes stay local. |
| [`&up` / module constants](doc/SPEC.md#state-groups-and-captured-layers) | Callable-type `&up` abstracts a closure environment; named local functions list captured bindings in `&up(...)`. Module/`sub` `let` (`ValueName`) and `meta let` (`ScreamingSnakeCase`, exclusive to `meta let`) constants are pure and need no `&up`; mutable/live top-level state is prohibited. |
| [Definition / callable target](doc/SPEC.md#callable-compatibility) | Named definitions spell exact exercised effects, state/provenance clauses, and return modes (`-> new`); anonymous closures infer them. Callable effect/state sets are upper bounds; access modes and return-source guarantees also match. Pure state reduction preserves return-source relations. Omitted sets are closed empty; `@`, `&`, and `@&` open compiler-tracked bounds on callable types (parameters, fields, collections; forbidden in `EffectOpDecl`) orthogonal to access modes. |
| [Snippets / complete source](doc/SPEC.md#document-conventions) | Every SPEC `ril` block is a self-contained, type- and access-checked snippet with complete signatures (`-- File:` / `-- Context:` for multi-file snippets). |
| [Purity / normal completion](doc/SPEC.md#failure-model-and-purity) | Immutable parameters with empty outward effects and empty state after local containment guarantee observational purity (deterministic, no host I/O or external mutation); purity promises no termination. `never` means no normal completion, including panic or `while true` without a targeting `break`. |
| [Fallible results / must-consume / panic](doc/SPEC.md#mandatory-inspection-of-fallible-results) | `!<T, E>` (`Result<T, E>`) must be inspected, propagated, handled, or returned (`E0720`; `_` does not inspect it). Must-consume linear values — both mode-free `ctl(...)` continuations and user-defined `[opaque] linear type`s (plus containers/composites thereof) — must be explicitly consumed (`E0625`; `E0549` on reuse or return-after-defer) and managed by an armed consuming `defer` across unhandled `ctl` calls. User-defined linear types allow pinned `let`/`let mut`, call-scoped `ref`/`mut` parameters (even when value-backed), `for ref`/`for mut` container traversal, and direct returns omitting `-> new` (`E0528` on consuming/returning through borrow). Partial indexing/slicing/map access (`xs[i]`, `s[a..b]`, `m[k]` reads and `m[k] += v`, `Array::{swap,insert,remove}`, `String::scalar_at`; `E0362`) and integer `/`/`%`/`<<`/`>>` (`E0361`) require static DBM proofs (via `if`/`while`/`for`/`match` narrowing, exact slice length conservation, or the Prelude proof Type Functions `NonZero`/`Nat`/`Positive`/`AtLeast`/`AtMost`/`Between`/`NonEmpty`/`Len`/`SameLen`/`InBounds`/`In` and combinators `Reflects`/`Implies`/`Ensures`, all invoked with `<...>` and supporting subject-type omission like `x: Nat`, `i: InBounds<xs>`, `k: In<m>`; or boundary `?[i]`/`?[a..b]`/`?[k]`/`Array::{first,last}`). DBM `unsat` directly proves branch exhaustiveness in `match`, `if/else if`, block tails, and irrefutable `let` (`E0345`) without introducing `@panic`/`@abort`/`@diverge`. Defects unwind LIFO `defer` cleanup; `Panic::recover` (`use ril/panic`) returns `!<T, Panic::Error>` (`Panic::Report`) and forbids outer live state, outer `ctl` handlers, outer must-consume captures, stateful outer `fn` handlers, and unhandled effects. Implicit `@panic`, `@abort`, and `@diverge` facts are inferred interprocedurally and surfaced in LSP / `ril inspect` rather than written in source signatures. |
| [Effect handlers / `defer` cleanup](doc/SPEC.md#deferred-cleanup-statements-defer) | Statement `with [ctl] Eff::op = [mode] expr` governs the remaining block/function; `with { ... }` scopes handlers strictly to its own body. `defer` registers lazy LIFO block cleanup on exit, early transfer, panic, and `unwind_ctl`; synchronous `@io`, `fn` effects, and `unwind_ctl(k)` are allowed, unhandled `ctl` is prohibited (`E0616`), and panicking operations/callees are statically prohibited (`E0627`). Handlers covering cleanup must precede `defer`. |
| [User / system effects](doc/SPEC.md#effect-declarations-and-handlers) | `eff` separates direct `fn` ops from one-shot algebraic `ctl` ops, both dispatched dynamically along the active call stack (closures and `where`-local `fn`s do not capture outer `with` handlers); handler-arm ops run against the handler's parent stack. `@io` is the sole lowercase built-in system effect, not a user-handler target. |
| [`ctl(...)` continuations](doc/SPEC.md#callable-types-and-signatures) | `ctl(...)` is a mode-free linear must-consume delimited continuation created solely by `with ctl` and discharged by direct root invocation `k(...)` or synchronous `unwind_ctl(k)` (`_` eagerly unwinds before the arm body). Operations returning `-> never` are abort-only: their handler arms omit `k` and unwind eagerly before running the arm body. `ctl(...)` forbids `mut`/`ref`/`^mut`/`new`/`var`, closure capture, cloning, and equality, and admits plain mode-free containers (`[]ctl(...)`, `[K: ctl(...)]`, `.{ k: ctl(...) }`, sums) with destructive extraction (`match`, `Array::pop`/`pop_front`/`remove`, `Map::replace`/`remove`/`pop_entry`) plus linear-safe `Map::contains`/`keys`. |
| [`clone` / `derive` / `Scoped<T>`](doc/SPEC.md#functional-updates-via-derive) | `clone` deep-copies `SharedObject` graphs into isolated `new T`, preserving internal aliases/cycles. `derive` updates immutable snapshots through confined `Derived<T>` paths (leaving the base unchanged) and forwards the `derive` closure's obligations. `with_scoped` introduces a lexically confined `Scoped<T>` view that cannot escape its callback (`E0607`), forbids by-value `inner(s)` (`E0406`), and permits `inner(ref s)` / `inner(mut s)`. Neither `clone` nor `derive` accepts value-type or must-consume roots. |
| [Built-ins / stdlib](doc/SPEC.md#named-function-declarations-and-contrast-matrix) | Bodyless `.ril` functions must match a registered primitive's module/name identity and signature. Built-in specifications determine phase (`len`, `inner`, `clone`, `derive`, `assert`, `panic`, and `String::inspect` are dual-phase); names alone grant no primitive behavior. Prelude does not export `ril/io`; use explicit `use ril/io` for best-effort non-panicking `Io::print` / `Io::println`. |
| [`fn` / `meta fn` / type functions](doc/SPEC.md#disjoint-call-families-and-branch-pruning) | Ordinary `fn` runs at runtime; `meta fn` produces type-value-free static data; type functions produce static type values. Runtime code enters compile-time evaluation explicitly via `meta expr` / `meta { ... }` (yielding immutable snapshots without `new`), `meta if`, and `meta match`; `meta fn` has no first-class runtime value. Static roots have an uncatchable compiler step limit (`E0811`). |
| [Static type values / ordinary data](doc/SPEC.md#static-type-values-and-type-quotation) | `Type<T>` is the exact static type of a type value representing `T`; bare `Type` is a kind. `<T>` quotes a type value, `<tv>` in a type unquotes it, and `typeof e` checks without evaluating `e`. Runtime storage cannot hold type values; generic `meta match <T>` resolves per concrete instantiation of `T`. |
| [Type / value arguments](doc/SPEC.md#generic-parameters-defaults-and-static-kinds) | Declared parameter kinds control generic arguments. Values and type values cannot supply type parameters; use `typeof e`. Type syntax adapts one-way to a `Type<T>` value parameter. `T: int \| f64` restricts a static domain; each call selects one concrete type, not a runtime union. |
| [Sum inclusion / subtyping](doc/SPEC.md#sum-variant-spreading-and-subset-conversion) | `..Sub` spreads variants; `?` widens included error sums, while ordinary values use `as Sup`. This is distinct from general subtyping. Extensible sums require a wildcard outside their defining package; closed records have no width subtyping. |
| [Data shape / field metadata](doc/SPEC.md#static-introspection) | `T.(k)` projects constituent data types; `Reflect::fields(<T>)` retains `(FieldMode, key)` pairs, while `Reflect::sum_tags(<T>)` lists sum tags and `Reflect::type_kind(<T>)` classifies `T`. Value-level payload projection requires matching or narrowing. |
| [`where` / checks & guards](doc/SPEC.md#dual-tier-where-invariants) | Braceless `where` hoists declarations: signature helpers admit `type`/`fn`/`meta fn`; trailing block helpers also admit `eff`. Static type checks preserve the checked type; static value checks / `\|> PascalCase` static proofs return `<()>` to accept or `<never>` to reject (zero runtime cost on parameters, returns, and immutable nominal/opaque type invariants, verified by DBM/static eval; `E0323`/`E0534`/`E0910`/`E0552`). `\|> snake_case` runtime signature guards invoke pure fallible guards at entry/successful exit. |
| [Equality / patterns](doc/SPEC.md#pattern-matching) | Data `==` requires the same type; static type values compare represented types by type equivalence. Binding patterns introduce names and unpack records, tuples, nominal `::(...)`, slices, ranges, and sum variants. |
| [Stable narrowing / live writes](doc/SPEC.md#flow-sensitive-type-narrowing) | Immutable paths narrow without a depth limit; the DBM prover + `while`/`for` widening fixpoint tracks divisor/shift (`E0361`), length/bounds/slice-length conservation and map/set `In<c>` key membership (`E0362`), branch exhaustiveness via `unsat`, immutable type-level invariants, and Type-Function static proofs (`E0323`). Overlapping writes, container resizing, map/set removals, active `defer` mutations, or open-state/open-effect calls invalidate affected live facts when independence is unproved (while preserving confined uncaptured locals). A `ref` alone proves no independence. |
| [Package / module / executable root](doc/SPEC.md#modules-and-compilation-units) | `pkg/...`, `ril/...`, and dependency roots resolve imports; `pkg` is package visibility. Files are modules; inline `sub`s are isolated and use `Super::` for parents. Executable roots are unimportable, forbid root visibility modifiers, and require private ordinary `fn main`. |
