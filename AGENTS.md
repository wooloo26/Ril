- **Consult [`SPECIFICATION.md`](./SPECIFICATION.md)**: The authoritative, code-first language specification is available in [`SPECIFICATION.md`](./SPECIFICATION.md) at the root. It contains all grammar constructs, operator precedence, type syntax, memory model invariants, algebraic effects, state capabilities, and normative code test examples needed for development.
- **Specification Omits Design Rationale**: The specification directly states syntactic and semantic rules without explaining design motivations or rationales (design rationale belongs in `DESIGN_RATIONALE.md`).
- **Language Rules Only (No Compiler Implementation Design)**: Specifications and documentation must focus strictly on language rules, grammar, typing rules, abstract machine semantics, memory model invariants, algebraic effects, state capabilities, and diagnostic error codes. Do NOT design or include compiler implementation details (such as toolchain CLI commands, compiler internal architectures/engines, lowering pipelines, IR/AST data structures, code generators, linker strategies, or runtime engines).
- **Code-First Principle**: Abstract textual descriptions must be prioritized around code snippets, using concrete and normative code examples to express rules and invariants.
