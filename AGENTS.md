# Repository guidance

## Editing restrictions

Do not modify `README.md` or `AGENTS.md` unless the user explicitly requests it.

## Git workflow

Work directly on `main` and commit changes there. Do not create, switch to, or
use other branches unless the user explicitly requests them.

## Ril distinctions

[SPEC](doc/SPEC.md) is canonical. Keep this guide focused on distinctions that are easily confused and affect interpretation or implementation. The table summarizes language rules and introduces no additional conformance requirements.

| Distinction | Ril meaning |
| --- | --- |
| [Checking / execution](doc/SPEC.md#complete-provenance-and-required-annotations) | Access modes, provenance, and effects, including Div, are static judgments; interfaces retain checking metadata. Authority modifiers are erased; mutation, copying, handlers, cleanup, and budget charging execute. |
| [Values / shared objects](doc/SPEC.md#types-and-memory-model) | `str`, `bytes`, and the zero-element tuple `()` copy by value; records, nonempty tuples, collections, and sum instances have object identity and may be aliased. Their objects are managed by tracing GC; shared-object status grants no shared write authority. |
| [Record forms / declaration bodies](doc/SPEC.md#record-types-and-row-polymorphism) | Record types, values, patterns, tests, mapped types, and variant record payloads all use `.{...}`. A type reference may prefix a runtime record expression, pattern, or test (`User.{...}`). Sum and effect declaration bodies retain outer `{...}`. |
| [Binding / access](doc/SPEC.md#binding-modes-and-storage-matrix) | `let` / `var` govern slot replacement. Plain bindings hold deeply immutable snapshots. `ref` may observe a live writable origin. Pinning fixes the target object even if its storage moves. |
| [`mut` / `^mut`](doc/SPEC.md#parameter-modes-caller-obligations-and-defaults) | Parameter `mut` grants temporary write access; `^mut` permits retained writers. Local `let mut` uses exclusive writable reception; `let ^mut` / `var ^mut` use shared writable reception. Actual origins and accesses determine exclusivity; `mut` alone does not prove unique ownership. |
| [Authority / reachable use](doc/SPEC.md#reachable-authority-use) | `var` requires reachable slot replacement; `mut` requires writable use; shared local bindings require shared reception and writable use. A `^mut` parameter requires retention beyond temporary call authority; writing alone is insufficient. Declared member schemas have no independent use requirement. |
| [`new` / isolation](doc/SPEC.md#construction-qualified-locals-and-mode-preserving-reception) | Construction qualification comes from checked initial reception. Handoff preserves allocation identity and ends the source path and derived accesses; root privacy and graph separation are independent checks. |
| [`via` / `infer`](doc/SPEC.md#access-mode-inference-with-via-and-infer) | `via` binds static access-mode parameters; `let via` requires dependent reception in a lexical mode template. `-> infer T` derives result modes and provenance, keeping `T` explicit, and requires explicit `via` in that ordinary Ril definition or callable type's parameter list, including written input schemas or callable parameters. A referenced type's hidden `via`, an enclosing signature, or the body alone does not qualify (`E0412`). |
| [Mode inference / storage replacement](doc/SPEC.md#member-modes-and-implicit-schema-parameters) | Reception authority comes from actual sources, not the requested receiver mode. Each concrete `via` storage instance has a fixed declared schema; later assignment checks that schema without re-inferring modes. `var via` permits slot replacement, not mode replacement. Implicit argument markers require verified lexical mode/callback dependencies; concrete operands retain explicit markers. |
| [Root / contained origins](doc/SPEC.md#return-construction-access-modes-and-sources) | `ref(x)` / `^mut(x)` select root origins from the formal's call-entry graph; `&return{...}` records possible contained origins. Root writable return accounts for its retention; writes and extra retention have separate state/provenance annotations. |
| [State / environment creation](doc/SPEC.md#state-and-provenance-tracking) | `&mut` records parameter writes, `&^mut` independent retained sharing, and `&capture` surviving environment creation. Local discharge follows actual origins and escape. |
| [`&up` forms](doc/SPEC.md#state-groups-and-captured-layers) | In callable types, bare `&up` abstracts an environment. `&up{...}` and `&up(sub){...}` identify concrete captured and module sources; their actual identities remain in metadata. Named definitions spell their required concrete source obligations. |
| [Closed / open callable rows](doc/SPEC.md#callable-contract-matching) | Closed rows require exact normalized effects, including Div, and state/provenance obligations. Omitted effects in a callable type exclude Div; open `@` preserves actual effects. Effect and state/provenance openness and access-mode polymorphism are independent. |
| [Inference / source annotations](doc/SPEC.md#mandatory-contract-inference-and-completion) | The compiler derives propagation and required annotations from starting access modes and constraints. Named definitions spell required concrete operational-effect and state/provenance annotations; inferred Div is retained automatically. Anonymous annotations are optional. `via` / `infer` retain their specified details in metadata. Explicit `@{}` closes the entire effect row, including Div. |
| [Fixtures / complete source](doc/SPEC.md#document-conventions) | SPEC fixtures may display compiler-completed named signatures; complete source spells the required annotations. |
| [Purity / halt / never](doc/SPEC.md#termination-and-halt-contracts) | Purity excludes outward operational effects and state/provenance obligations after handling and local discharge; Div may remain. Optional `halt` additionally excludes Div for every admitted invocation, including defaults; it installs no budget and changes no call family. There is no separate `Finite` / `MayDiverge` callable judgment. `never` means no normal continuation; finite computation may panic. |
| [Div / budget exhaustion](doc/SPEC.md#finite-evaluation-with-div) | Div is a compiler-owned effect label for possible divergence, with no operations or source handlers. Recursion and `while` / `loop` introduce Div even with decreasing arguments or finite-looking conditions. Dual-phase `div_budget(limit: u64, action)` removes only covered invocation Div and returns `Result<T, BudgetError>`; exhaustion is `Err(BudgetError::Exhausted)`. Other effects/state and argument/recovery obligations remain; cleanup must independently be Div-free. Charging bounds abstract evaluation events, not wall-clock time. |
| [Source / compiler budgets](doc/SPEC.md#pure-type-functions-and-result-restrictions) | Static roots, including `halt` calls and source budgets, remain under the compiler's evaluation limit. Compiler exhaustion is uncatchable `E0811` and cannot discharge Div; source exhaustion returns ordinary Result data. Partial type previews are diagnostic data only, never valid types or budget-result payloads. |
| [`clone`](doc/SPEC.md#deep-immutability) / [`derive`](doc/SPEC.md#functional-updates-via-derive) | `clone` yields isolated `new T` for ordinary shared objects. A plain value-type input fails `SharedObject` (`E0301`), and a value-type `ref` argument is `E0401`. `Channel::clone_sender` is a separate endpoint operation under `@Fiber`. `derive` confines path updates to a `Draft<T>`, forwards recipe obligations, and publishes an immutable snapshot. |
| [Built-in signatures / primitive contracts](doc/SPEC.md#built-in-foundational-operations) | Built-ins use ordinary Ril signature forms. Guards and access modes resolve statically. Primitive contracts supply eligibility, phase, and execution rules. `len` uses ordinary immutable reception in static evaluation and also admits `ref` collection observation at run time. |
| [Bodyless built-ins / foreign declarations](doc/SPEC.md#named-function-declarations-and-contrast-matrix) | A bodyless `fn` in `.ril` must match a registered primitive's module/name identity and signature (`E0902` / `E0909`); the same name in another scope grants no built-in behavior. `pub` independently controls visibility. Foreign host contracts remain in `.d.ril` under their own body-prohibition rules. |
| [Phase barrier / static specialization](doc/SPEC.md#pure-type-functions-and-result-restrictions) | Type tokens and type patterns are static. Generic `fn` bodies may use static type metadata such as `match <T>` for specialization; runtime values, storage, and captures cannot materialize tokens (`E0816`). Type metadata is erased, and static specialization grants no cross-family call exception. |
| [Static types / ordinary data](doc/SPEC.md#static-type-values-and-type-quotation) | `Type<T>` is an exact static metatype; `<T>` is a static type token. Bare `Type` is a parameter/kind sort, not a value annotation. `typeof e` checks without evaluating `e`. Eligible token-free meta results may become ordinary constants; `meta fn` cannot return tokens or type-producing authority (`E0812`). |
| [Type arguments / value arguments](doc/SPEC.md#generic-parameters-defaults-and-value-sorts) | The declared parameter sort controls generic arguments. Ordinary values and quoted tokens cannot supply type parameters (`E0306`); use `typeof e` when the value's type is intended. Static values go to declared value-sorted parameters; type syntax may adapt to a `Type<T>` value parameter, never the reverse. |
| [Closed type sets / runtime unions](doc/SPEC.md#generic-parameters-defaults-and-value-sorts) | `T: i64 \| f64` and `\T: i64 \| f64` restrict static domains; every member is checked and each call specializes to one rigid type before signature type functions evaluate. Matching all declared members is exhaustive; a redundant `_` arm is `E0304`. Passing an unspecialized set is `E0306`; type functions do not distribute over sets, and results must be single rigid types (`E0318`). Runtime alternatives use tagged sums. |
| [Data type / member metadata](doc/SPEC.md#static-introspection) | `T.(k)` projects constituent data shape. `coords(<T>)` enumerates record/tuple `(MemberMode, key)` pairs, retaining both slot replacement and access; `variants(<T>)` enumerates sum tags. Value-level sum payload access still requires matching or narrowing. |
| [`where` / generic constraints](doc/SPEC.md#dual-tier-where-invariants) | `where` declares helpers; generic predicates use signature constraints and pipeline guards. Signature helpers are types; block helpers may also be functions or effects. |
| [`is` / equality / binding patterns](doc/SPEC.md#value-tests-with-is) | `is` is asymmetric, non-binding pattern testing of tags, shapes, ranges, and record subsets; `==` is symmetric same-type equality. Test leaves read existing values or evaluate expressions, with structural short-circuiting. `match` and guarded bindings introduce payload names. A failed payload comparison alone does not exclude its variant. Type patterns match static tokens. |
| [Stable narrowing / live writes](doc/SPEC.md#flow-sensitive-type-narrowing) | Immutable `let` paths through immutable fields narrow without a depth limit. Overlapping assignment or writes, including expected-expression writes during `is`, invalidate affected facts; a `ref` does not prove independence. Loop refinement converges over the finite-height variant/optional lattice. |
| [`sub` / executable root](doc/SPEC.md#modules-and-compilation-units) | Library files and inline `sub PascalCase` are `sub`s; the executable root is non-`sub`, unimportable, forbids top-level `pub`, and requires a non-public ordinary `fn main`. `halt` is allowed on `main` under its usual checks. Inline `sub` is hermetic: `Super::` reaches enclosing non-mutable items, downward access requires `pub`, mutable static state is never `pub`, and `opaque type` transparency stays in its exact defining scope. |
